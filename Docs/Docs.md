## 2. Цель проекта
Ключевой целью проекта является отслеживание времени затраченного на ту или иную задачу. Программа базируется на экранном времени пользователя, который, к примеру, работает на удалёнке, либо на каком-то-либо предприятии, где важно вести отчётность по часам.

Проблематика: халатность рабочего класса/процесса.

## 6. Функциональные требования

### FR-1. Работа с базой данных
**Описание:** соединение с БД,
выполнение SQL команд,
добавление пользователей,
получение данных пользователей
**Входные данные:** информация о пользователе/программе
**Результат:** получение готовой базы данных с таблицами и информацией о пользователе/программе в этой базе данных

### FR-2. Регистрация пользователя
**Описание:** ввод логина и пароля,
отправка данных на сервер,
сохранение пользователя в базе данных,
проверка уникальности логина
**Входные данные:** логин, пароль
**Результат:** пользователь создаётся в базе данных

### FR-3. Авторизация пользователя
**Описание:** ввод логина и пароля,
отправка данных на сервер,
проверка данных в базе,
возврат результата авторизации
**Входные данные:** логин, пароль
**Результат:** вход в аккаунт, в иных случах сообщение об ошибке

### FR-4. Клиент-серверное взаимодействие
**Описание:** подключение клиента к серверу,
отправка запросов (login, registration),
получение ответов,
обработка ошибок соединения
**Входные данные:** данные о клиенте/приложениях
**Результат:** клиент и сервер общаются и обмениваются данными, сервер передаёт необходимые данные в БД

### FR-5. Управление соединением сервера
**Описание:** запуск сервера,
приём подключаемых клиентов,
обработка нескольких запросов,
закрытие соединения
**Входные данные:** отсутствуют
**Результат:** запущенный сервер может открывать и закрывать соединения с клиентами

### FR-6. Интерфейс клиента
**Описание:** регистрация,
вход,
отправка данных на сервер,
отображение сообщений об ошибках
**Входные данные:** IP адрес и порт сервера
**Результат:** клиент подключается к серверу и может обмениваться данными с ним

## 7. Нефункциональные требования

### Производительность:

время обработки запросов - не более 2 секунд сервер поддерживает одновременную работу нескольких клиентов, время установления соединения с сервером составляет не более 3 секунд. При подключении новых пользователей сервер сохраняет стабильность
### Надёжность:

при возникновении ошибок система уведомит пользователя о них.
Сервер продолжает работу после отключения одного из клиентов.
Программа должна предотвращать повреждение данных при сбоях.
Программа корректно обрабатывает исключения при работе с сетью и/или базой данных

### Удобство интерфейса:

интерфейс прост и понятен обычному пользователю. Пользователь должен получать уведомления о результате операций

### Ограничения:

приложение только для Windows. Клиентское приложение не должно иметь доступа к базе данных напрямую

## 8. Сетевое взаимодействие
- используемый протокол: TCP
-порт сервера: 5000
- формат сообщений: имя/пароль
- схема обмена: Клиент → Сервер → База данных → Сервер → Клиент

## 9. Структура базы данных 

### таблица Users

| **Поле** | **Тип** | **Описание** |
| -------- | ------- | ------------ |
| _Id_  | _Primary Key_ | _Хранит ID пользователя_ |
| _UserName_ | _String_ | _Хранит имя пользователя_ |
| _UserPassword_ | _String_ | _Хранит пароль пользователя_ |
| _Connect_ | _String_ | _Сообщение о подключении/отключении пользователя_ |
| _DateTime_ | _datetime_ | _Пишет, когда пользователь подключился/отключился_ |

### таблица TrackerData

| **Поле** | **Тип** | **Описание** |
| -------- | ------- | ------------ |
| _IdUser_ | _Int_ | _Хранит идентификатор пользователя из таблицы Users_ |
| _NameApplication_ | _String_ | _Хранит имя запущенного приложения_ |
| _TimeUse_ | _Int_ | _Хранит время использования запущенного приложения_ |
| _LaunchDate_ | _datetime_ | _Хранит время запуска приложения_ |
| _Closing_date_ | _datetime_ | _Хранит время закрытия приложения_ |
